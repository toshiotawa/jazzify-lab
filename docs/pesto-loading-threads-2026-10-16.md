# PESTO 配信・スレッド・バッファ改善（2026-10-16）

## 変更

1. 分離されたゲーム文書で、SharedArrayBufferと2コア以上に対応するときだけWASMを2スレッドへ。その他は1スレッド。診断に実スレッド数を追加。
2. `onnxruntime-web/wasm`だけをimport。GPU実装をWorkerから除外。
3. compact-v2 ONNXをビルド時に復元して直接配信。ブラウザで元モデルの取得・差分JSON解析・再構成を行わない。
4. q=2/4デシメータの係数を初期化時に保存し、出力バッファを再利用。

モデルの学習係数、tracker、推論間隔は変更しない。完成済みモデルは旧配信の復元結果と同じ11,150,637 bytes、SHA-256 `c50ca16a07297ddc2b788403268a43736cceb792ec599746da7d5486bca974b8`。

## 配信・画面遷移

NetlifyのCOOP/COEPは `/main/play` と `/main/play/*` に限定。外部動画を表示するレッスン詳細、認証、アカウント・決済、LP、ブログ、外部埋め込みは対象外。分離境界をまたぐSPA遷移では同じURLを文書として再読込する。ゲーム画面同士では再読込しない。URLのquery/hashを保持し、未対応環境で再読込を繰り返す処理は入れない。

ヘッダーは `same-origin` / `credentialless`。`/assets/*`、`/ort/*`、`/js/audio/*` のWorkerスクリプトにもCOEPを付与。WASMのmjs URLには固定のCOEP世代queryを付け、旧immutableレスポンスのヘッダーキャッシュを回避する（wasm本体は再利用）。既存のCORSを要求する通信は継続する。外部no-corsリソースはcredentiallessとなる。実ユーザーのログイン・決済・非公開動画、Safari/Firefox実機を操作する試験は行っていない。

Vite pluginはチェックイン済みの元ONNXとv2差分をビルド時に検証し、distに完成済みファイルを生成する。開発時もサーバー起動時に1回だけ生成する。既存のimmutableモデルは旧クライアント向けに保持。新URLに同じv2 IDの完成済みモデルを配信する。

## 正しさ

- 本番配信モデルのSHA-256・サイズ一致。破損・HTTP失敗・切り詰め・不正差分は拒否。
- q=2/4の連続PCMと途中resetは旧実装の出力ハッシュと厳密一致。
- 低音域の推論を未完了にした状態で追加チャンクを送り、実行中のtensorが変化しないことを確認。
- ゲーム境界の再読込・ゲーム間の再読込なし・query/hash維持・非ゲーム文書のヘッダー除外をテスト。
- 実ブラウザWASMでSalamander/Feltのフレーズと同音連打から各2秒、計1,600フレーム。同一PCMを1/2スレッドへ入力し、prediction・confidence・volumeの最大差は全て0。cacheも原音履歴と厳密一致。

## 性能への影響

新しい本番の毎フレーム処理、タイマー、polling、高頻度React state更新、hot path allocationは追加しない。係数計算とオブジェクト作成を初期化に移し、低音域の出力sliceを削除。追加メモリは係数1組／デシメータとONNXの補助スレッド。スレッド間同期やメモリ消費は端末に依存する。

cold取得時のモデル本体＋差分は17,063,136→11,150,637 bytes（34.7%減）。WASM本体は同じ。Vite本番Workerは89,775 bytes（gzip 27,272 bytes）。旧Workerのesbuildブラウザminify値は508,309 bytes（gzip 122,714 bytes）。転送圧縮方式・CDNキャッシュにより実転送量は異なる。

## 再現

`scripts/pesto/README.md`の2スレッド検証とheadroom試験を参照。同じ録音PCMのSHA-256をスクリプトが照合する。2分試験は本番AudioWorklet/Worker/WASMを使用するが、実マイク・ゲーム描画・他のアプリ負荷は含まない。推論のwindowsは診断末尾128観測を約300msごとに取得したsnapshotの分布であり、全推論の直接の分位数ではない。

Chrome Headless 153、48kHz、5ms周期。同じ4録音ピアノをループして実時間で入力。1スレッドは非分離、2スレッドは分離文書で実行した。診断の `wasmThreads` もそれぞれ1/2を確認。

今回の比較では推論中央値約36%短縮、欠落合計約33%減。ただし欠落は解消していない。共有Linux検証環境の単一ペア測定で、全ユーザーへの保証ではない。逐次出力比較の終了付近は1スレッド試験の起動付近と一部重なる。意図的なストレスタイマーは追加していない。旧レポートの70msは別の試行・Chrome環境なので、この210/140msとは直接比較しない。2分試験後の差分はmjsのキャッシュ世代queryだけで、最終ビルドでも別途5秒試験で2スレッド初期化・推論成功・Worker error 0を確認した。
