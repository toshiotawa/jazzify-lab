# Pitchy: 音替わりでの前音再発音を抑える修正と再測定

2026-10-16。比較元は stg `ef63d3bd44524de0c9c8ad60bc047b092404460f`。

## 修正範囲

Pitchy の自由入力で同音の再発音を判定するとき、従来の全体音量の立ち上がりに加えて、保持中の音の帯域でも立ち上がりがあることを必要とする。次の鍵盤の打鍵直後は、4096サンプルの解析窓が前音を返す場合がある。全体音量の上昇だけで前音を連打として通知していた経路を抑える。

PESTO はこの追加条件を無効にする。解析窓、感度、信頼度閾値、解析間隔、音替わりの安定判定、正解音補助、譜面指定の同音連打判定は変更していない。追加の確認待ち時間もない。

## 同じピアノ音声での再測定

前回の Salamander / Felt 2音源の147条件を10msで再実行。以前と同じ28条件を5msと20msでも再実行し、合計203実行。48kHzの既存PCMをそのまま使用。単音、100/150/250/500msの音替わり、100/125/200/300msの同音連打、音量差、ノイズ、残響・重なり、低音モードなどを含む。

正しいMIDIを、打鍵後250ms以内かつ次の打鍵前に通知した場合を1対1で対応づける。余分な発音は、その対応に入らない noteOn。遅延は遡及された onset 時刻ではなく、実際に通知したPCM位置で評価する。処理時間・キュー待ちはこのオフライン遅延に含まない。

| 10msの条件 | 修正前 | 修正後 |
| --- | ---: | ---: |
| 音替わりの正しい音 | 64/64 | 64/64 |
| 音替わりの余分な発音 | 40 | 3 |
| 音替わり通知遅延・中央値 | 70ms | 70ms |
| 同音連打・補助なし | 96/96 | 96/96 |
| 同音連打・補助あり | 96/96 | 96/96 |
| 全147条件の正しい音 | 423/460 | 423/460 |
| 全147条件の余分な発音 | 133 | 20 |

全203実行で、正しく拾えた音の数と各音の通知遅延は完全一致。余分な発音が増えたケースは0。38,409観測の生の推定ピッチ、信頼度、音量、フレーム番号も一致した。オフラインでは全実行でPCM欠落・エラー0。

5msの28条件は、正しい音143/144を維持し、余分な発音55→15。20msの28条件は、正しい音90/144、余分な発音2で変化なし。5/20msの28条件と10msの147条件の集計は母集団が違うため、そのまま優劣比較しない。

10msで残った音替わりの余分な3回は Salamander の250ms間隔で1回、500ms間隔で2回。帯域内のエネルギーも増えるケースは、この追加条件だけでは除けない。未検出音や20ms設定の連打取りこぼしの改善は今回の対象外。

集計と音声マニフェストSHA-256は [JSON](./pitchy-retrigger-fix-2026-10-16.json)。前回の比較データ一式にある `tools/run_comparison.mjs` を今回のソースに対してPitchyのみ実行し、同じ `tools/analyze.py` の `score` / `aggregate` で採点した。修正前の結果ファイルは保持し、今回の結果は別名で出力した。PESTO の音声再測定は今回は行っていない。

## 回帰確認と負荷

回帰テストで、全体音量だけが増える音替わり、実際の同音連打を同じフレームで受理すること、帯域の揺れだけでは連打にしないこと、PESTO既定動作を確認した。

既存の全体音量判定を通った再発音候補に限り、既存の短い帯域履歴を走査する。通常設定は2観測分。新しい配列生成、タイマー、高頻度React状態、確認待ちは追加していない。
