# PESTO 未使用音源の補完比較と独立基音診断（2026-11-05）

**zerosへ一括切替は採用しない。ギター等の平均音高は改善したが、同じ楽器内にもconfidence付きrecallの悪化があり、低音ベースの検出も解決しなかった。** 今回はウェイト・配信モデル・ゲーム判定を変更せず、評価コード・固定音源リスト・診断・再現手順を追加した。基準stgは`ba5db928e50549f5108a95ba9bce6464534845e3`。

## 範囲と比較条件

前回未評価の12音源グループ・60音を、モデル出力を見る前にID・音域・取得可能なvelocityから選定した。NSynth acousticの鍵盤/ギター/フルート/金管/歌声が各2音源ID、別ピアノ実録音（Iowa Steinway Model B）が1個体6音、未評価の同梱Finger Bass元録音が1音源3音。前回の11 NSynth IDとFelt Pianoは新規群へ混ぜない。既存70音・12音源グループは開発用対照として別集計した。新規群も今後は調整用validationであり、以後の最終testにはしない。

新規群は発音前無音を揃えるため、最初の2秒で原音エネルギーから発音位置を検出し、20ms前から800ms切り出した。Iowa録音には100〜500ms程度の先行無音があり、そのまま100msで人工切断すると音が入らないためである。既存群は従来の先頭800msを維持した。両群の絶対値の差をモデル改善量として扱わない。同じ群・同じ音・同じPCMでのモデル差だけを比較する。

各音をclean（600ms+200msゼロ）、100ms人工短音、200ms人工短音の3条件にし、各々に末尾2ms fadeを適用。計390の入力条件、各39,000フレームを、Python refill/Python zeros/配信refill ONNX/新規zeros ONNXの4経路で実行（計156,000回の5ms推論）。学習済み係数は同じで、Python同士は補完だけを変える。48kHz/240 samples/3976-sample cacheを固定し、各条件で履歴を初期化する。tracker・期待音・音程補正は使用しない。

## 平均の改善で隠れる悪化

名目ラベルとの相違8音を除いても、新規群には解析参照上の悪化行が46件ある。これは音源×条件×phase×指標の重複する診断行で、独立した46録音の悪化ではない。

例えばclean持続部のconfidence付きrecallは、`guitar_acoustic_002-072-100`で80.0% → 45.7%、`keyboard_acoustic_003-084-025`で54.0% → 23.0%。ギター全体の平均が改善していても、同じ楽器内の既に読めていた音を取りこぼす。旧70音の対照群でも、解析参照上のフルートrecallは76.1% → 69.1%、ベース55.6% → 49.2%で、従来のトレードオフが残った。

各音源×条件×phaseで1 percentage point超の悪化を検出する比較は、新規群・旧群とも`do-not-promote`。名目ラベルと推定基音が衝突する例の影響を別に確認しても、切替を支持する結果にはならない。

## 判断・追加学習

1. zerosへの一括切替、楽器別の自動切替、一律の音程補正は今回導入しない。平均改善だけでは他の音の悪化を防げない。
2. 次の精度改善には、低音ベース・弱音ピアノ等で音高推定と有音判定を分けた原因調査が必要。confidenceは音程正解率ではなく有音/無音のclassifierで、閾値を一律に下げるだけでは誤音高を直せない。
3. 追加学習は今回実施していない。検討するなら、正解F0と有音区間が確認された別録音を用意し、複数楽器の個体・歌い手・録音セッション単位でtrain/validation/final testを分離する。今回見た130音を最終testに再利用しない。元モデルの学習素材との完全非重複も今回保証しない。

## 再現・変更範囲

[scripts/pesto/README.md](../scripts/pesto/README.md#未使用音源でのrefillzeros比較と独立した基音確認)に準備・固定upstream・実行・終了コードの意味を記載した。音源は`padding-holdout-sources.json`でSHA-256固定し、外部音声はGitへ追加しない。[測定JSON](pesto-padding-holdout-2026-11-05.json)にはsource/PCM/model SHA、全Python評価行（列定義付き配列）、各楽器集計、個別悪化、到達不能数、基音診断、厳密照合の不一致例を保存した。ONNXの整数評価指標はPythonとの差分がある行だけを追加保存し、全行は評価コマンドで再生成できる。全フレームの基音推定は`--reference-traces`で再生成する。
