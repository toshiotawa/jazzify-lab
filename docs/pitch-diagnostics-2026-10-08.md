- 48kHz・240サンプル（5ms）単位の推論に処理が追いつかず、取り込み側の40ms上限で古い待機音声が破棄される。

## 修正

通常音域のモデルcacheは直前3976サンプルの実PCMであり、Workletの復元履歴から完全に復元できる。既存の実ONNX検証スクリプトで、復元後のprediction・confidence・volume・cache_outが連続推論と一致することを確認する。

この完全な復元に成功した場合、持続音・期待音の安定判定・同音連打ゲートを保持し、冷起動用warmupを再開せず判定を継続する。アタック包絡も実PCMから復元し、短い空の窓が育つ過程をアタックと誤認することを防ぐ。

復元履歴が不足・非有限値を含む場合、履歴がない場合、原音PCMをそのまま使えない低音シフトでは従来の冷起動とwarmupを維持する。世代変更や推論エラーのリセットも維持する。

判定設定の生成は感度・安定フレーム数・シフト変更時に限定し、各推論フレームでの計算とオブジェクト生成を削除した。アタック包絡への履歴取り込みは最後の1024サンプルだけを処理し、既存の固定バッファを使う。

## 検証と限界

- 欠落が毎観測の前に発生する条件の回帰テストは、修正前に認識0件で失敗し、修正後に持続音を1回だけ認識して成功。
- 同音待ちの維持、次の期待音への切替、無音でのnoteOff、不正な履歴の冷起動、低音シフト、世代変更、バッファ返却のテストは成功。
- 実WASMの`node scripts/pesto/verify-pesto-gap-recovery.mjs`は成功。3200フレーム中、542フレームを欠落させて68回復元し、保持した2658フレームの4出力は連続推論との差がすべて0だった。
- `npx tsc --noEmit`、`npm run lint`、`npm run build:app`は成功。lintのエラー・警告は0。ビルドは既存の依存・チャンク分割に関する警告を出す。
- `npx ts-prune`は1395行を報告し、うち1072行はモジュール内使用、323行は未使用候補。変更前のHEADをメモリ上で解析した結果と比較し、新規の候補がないことを確認した。既存候補の整理は今回の修正範囲に含めない。
- 全テスト初回は2335件成功、2件が既存の5000ms制限でタイムアウトした（2分間の取り込みシミュレーションと10分間の音声ミックスシミュレーション）。他の検証プロセスを終え、`npm test -- --testTimeout=20000`で再実行し、311ファイル・2338件すべて成功。タイムアウトした2件は再実行時に約4.8秒・4.4秒で通過した。テストの判定条件とリポジトリの設定は変更していない。
- 新しいフレームループ・タイマー・ポーリング・React state更新は追加しない。包絡の履歴復元は欠落イベント時だけ行い、新しいバッファを生成しない。
- モデル自体の演算量や5ms入力単位は変更していない。実機Chromeでの推論時間短縮は保証しない。
- 観測間に落ちた短い音の全検出は保証できない。低音シフトの欠落復帰は引き続きwarmupを使用する。
