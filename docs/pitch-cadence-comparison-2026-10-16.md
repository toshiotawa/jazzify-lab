# PESTO 5/10/20ms比較と未認識の切り分け

対象ベース: stg `c825b3868ead7b6442a2efadb700d4994a695155`。

## 結論

既定の5msを維持する。10ms/20msは診断設定で比較できるようにするが、一律の置き換えはしない。**同じ原音終了時刻でモデル出力が一致することと、発音イベントを同じように検出できることは別**である。

10ms/20msではONNX実行回数は100/50回毎秒（通常音域）。モデルが推論しない5ms分も、3976サンプルのPCM cacheへ追加する。音声のリサンプリングや単純な間引きで負荷を減らさない。アタック包絡には全PCMを追加する。入力の5ms転送、40msの待機上限、単一WASMスレッド、判定のconfidence/dB基準は維持する。

## 停止原因について確定した範囲

1. **負荷による観測欠落**。過去の実ログには推論約8〜11msと、5ms周期の処理予算超過・35ms欠落の反復がある。Workletは転送2枠と40msの待機上限を持つ。Workerが追いつかなければ、古い待機PCMを捨てる。この経路はコードとログの双方で確認できる。
2. **履歴復元後も入力レベルが低い未認識**。`docs/pitch-diagnostics-tail-2026-10-08.md`では、50.713〜55.488秒の観測で原音RMSが−68〜−62.6dBFS、confidenceが約0.013〜0.031。AudioContext/track/推論は継続、reset/warmupは0。欠落の観測より前に低入力が始まっている。これは「Workerが定期再起動した」だけでは説明できない。
3. 現行Workerには推論を定期再起動するタイマーはない。通常音域の完全なPCM復元後の再warmup回避はすでに実装済み。今回、これを新しい修正として数えない。

入力レベル低下の上流原因（ブラウザの入力処理、Apolloのルーティング/ゲイン、取得チャンネル等）は未確定。既存のチャンネル選択・echoCancellation切替は保持する。合成信号の検証から実機マイクの上流原因は特定できない。しきい値を引き下げて見かけの停止だけを消す変更は行わない。

## 実装

- 音声設定の「音声入力の診断ログ」に、5/10/20msの比較用選択を追加。既定5ms。切替時だけ既存の直列接続処理で再接続する。入力デバイス・チャンネル・echoCancellationを保持。選択は再読み込みまで。
- Workerはモデル入力240サンプルを保持。推論しないフレームは事前確保済みcache内の`copyWithin`/`set`で履歴を更新する。欠落復元、冷起動、世代変更では推論位相も初期化する。
- アタック包絡は推論の前に全原音を受け取る。従来、低音モードの出力が240サンプル分揃わない場合、包絡への原音追加までスキップされていた経路も修正する。
- trackerの時計・release・最短発音・再発音guard・lookback・warmupを実周期へ合わせる。安定判定の観測数と期待音補助の確認回数は維持する。少数の観測を複製して安定判定を通すことはしない。このため短い音に対する判定時間は長くなり得る。
- 低音シフトの実周期は`max(選択周期, 5ms × 間引き係数)`。+12は最短10ms、+24は最短20ms。低音のフィルタ済みcacheを原音で上書きしない。
- 診断JSONに実推論周期、推論完了数、意図的な推論省略数、−60dBFS未満の観測数、confidence棄却数を追加。省略数は音声欠落数と分ける。monitorは欠落のない通常音域で約300msを維持。低音モードでも約300msにそろえる（従来は+12で約600ms、+24で約1200ms）。通知は低頻度のままで、10/20ms化によって診断が遅くならない。

## 実WASM・本番Workerの逐次再生

再現スクリプト: `node scripts/pesto/compare-pesto-cadence.mjs temp/pesto-cadence/results.json`。数値は[逐次再生のJSON](./pitch-cadence-comparison-2026-10-16.json)。

本番Worker、実tracker、配信中のcompactモデルを復元する実ローダー、onnxruntime-web単一スレッドWASMを使用。合成信号を2秒ずつ、5/10/20msに対し同じ原音で逐次再生した。実時間で取り込む負荷試験ではない。

- 16条件: 持続音、100/125/200ms間隔の減衰連打（各0/5/10/15ms開始位相）、音程変化、混合音域、途中からの低入力。
- 通常音域で10ms版3200回、20ms版1600回の推論を実行。warmup後の合計4752観測について、同じ原音終了時刻の5ms参照に対しprediction/confidence/model volumeの最大差は0。
- 持続ミの発音は全周期で1回。最初の受理は5ms: 30ms、10ms: 40ms、20ms: 60ms。
- 200ms間隔・開始位相5msの減衰連打は、5ms: 9回、10ms: 0回、20ms: 0回。100/125ms間隔でも取りこぼす条件があった。推論負荷を減らしても、短いconfidence成立区間を複数回観測できない場合は発音を確定できない。
- アタックdBは、判定器が保持している測定音が周期により異なる場合、同じ時刻でも一致を要求しない。音程値の一致だけでオンセット性能を保証しない。

この合成信号はピアノ録音の代用ではなく、RPAやピアノ正答率の測定ではない。上記の取りこぼしは既定値を変えない判断材料として扱う。Nodeでの処理時間には他の検証との同時実行が含まれるため、性能比較の根拠には使わない。

## 本番ブラウザの長時間入力

[ブラウザ結果JSON](./pitch-cadence-browser-2026-10-16.json)。本番ビルドのAudioWorklet → MessagePort → Worker → WASMを使い、440Hzの持続信号を各120秒入力した。Linux x86_64、Chromium Headless Shell 134.0.6998.35、単一スレッドWASM、crossOriginIsolated=false。通常Chromeの起動が実行環境のUnix socket制約で失敗したため、Headless Shellを使用した。

| 選択周期 | 欠落回数 | 欠落PCMの合計 | reset | PCM履歴復元 | 発音 / 誤音 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 5ms | 1414 | 49.630秒 | 0 | 1414 | 1 / 0 |
| 10ms | 755 | 26.600秒 | 0 | 755 | 1 / 0 |
| 20ms | 17 | 0.910秒 | 0 | 17 | 1 / 0 |

全条件でエラー0、lowInputFrames=0、confidence棄却0。5msの終盤の推論P50は7.7ms、10msは9.1ms、20msは10.8ms。5msの処理予算超過による欠落と、resetなしでのPCM復元を実ブラウザで再現した。10msにも欠落が残り、20msでは大幅に少なかったがゼロではない。

5ms試行前半は全体テストと重複している。10/20ms試行は他の検証完了後に行った。共有実行環境のCPU速度も変動するため、欠落量の倍率や推論時間の絶対値を一般化しない。ブラウザのfirstNoteMsには起動・配送負荷を含むので、周期そのものの遅延比較には使わない。

実マイク・Apollo・ゲーム描画は含めない。持続音の検出継続は確認できたが、欠落区間のアタックを復元できたことにはならない。負荷による観測欠落の検証と、実演奏の認識精度の検証を混同しない。20msで負荷が下がった事実を、短い音の認識性能が保たれた根拠にしない。
