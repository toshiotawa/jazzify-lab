# ブラウザ版 Pitchy 比較オプション

音声入力設定の「音程の認識方式」で PESTO / Pitchy を切り替える。通常設定と Phrase Defense のチュートリアルに表示し、`gameSettings.voicePitchEngine` に保存する。既定は PESTO。切替時は既存の直列化された接続処理で Worker、マイク、AudioContext を解放して再接続する。5/10/20ms 更新間隔の変更でも選択方式を保持する。

## 実装と比較条件

- Pitchy 4.1.0 (MPM)、48kHz、4096サンプルの移動窓（約85.33ms）。低音読み取りONでは既存の間引き・実音復元を共用するため、原音の窓は約170.67ms。
- 5/10/20ms は推定の更新間隔。窓長でも処理時間でもない。低音モードの最小更新間隔は既存仕様どおり10ms。
- Capture Worklet、転送バッファの再利用、キュー、原音のアタック包絡、PitchOnsetTracker、期待音補助と同音連打判定を共用する。
- PitchyではONNXセッション・モデルを初期化しない。検出器・PCM窓・返却フレームは接続時に確保して再利用する。Pitchy内部には小さな一時配列の割当がある。
- PitchyのclarityはPESTOのconfidenceと同じ尺度ではない。既定感度5では採用下限0.875、即時発音/高速レガートは0.95。混在音窓による低い偽音を抑えつつ、減衰する単音の立ち上がりを採用するための初期値。実楽器での最適値は未評価。
- 窓内に2周期未満しか収まらない推定は不採用。音量ゲートは最新チャンクの線形エネルギーを使い、窓内の古い音だけで離鍵を遅らせない。
- Pitchyの入力欠落時は窓を破棄して再充填する。PESTO用3976サンプルの復元履歴をPitchyの4096サンプル窓に流用しない。
- 診断JSONの`modelId`と接続ログの`pitchEngine`で方式を識別する。

## 検証

合成音のテストは、倍音を含むMIDI 33/45/60/69/84/96を10cent以内で推定、無音時の離鍵、音程切替、5/10/20ms、期待音の同音連打、低音モードの実音復元、欠落後の復帰を確認する。UIと接続テストで選択保存、再表示、エコー設定変更、方式・更新間隔の切替時の保持と発音中ノートの解放を確認する。PitchyでONNXモデルを読まないこともテストする。

ローカルheadless Chromium 153、productionビルドの実Worker/AudioWorklet、440Hz持続音、crossOriginIsolated=falseの結果:

| 更新間隔 | 時間 | 入力欠落 | 不連続 | 誤音 | エラー |
| --- | ---: | ---: | ---: | ---: | ---: |
| 5ms | 10秒 | 0 | 0 | 0 | 0 |
| 10ms | 120秒 | 0 | 0 | 0 | 0 |
| 20ms | 10秒 | 0 | 0 | 0 | 0 |

10ms試験は12,000回の推定、推定時間p95約0.6ms、最初の発音通知約102ms。初回通知時間は推定処理時間と異なり、窓充填・音声コールバック・判定待ちを含む。この数値をマイク入力の総遅延とは扱わない。生データは`pitchy-browser-2026-10-16.json`。

合成持続音の試験は、実ピアノ、マイクのエコー抑制、部屋の残響、速いフレーズ、Safariでの精度・安定性を証明しない。PESTOより高精度だとは判断しない。比較時は同じ入力チャンネル、エコー設定、感度、低音設定、更新間隔を使い、音程誤り・同音連打・短音の取りこぼしを別々に確認する。

再現コマンド（PlaywrightとChromiumが利用できる環境）:

```sh
npm run build:app
PESTO_BENCHMARK_ENGINE=pitchy PESTO_BENCHMARK_INTERVALS=10 PESTO_BENCHMARK_SECONDS=120 node scripts/pesto/benchmark-pesto-browser.mjs /tmp/pitchy-browser.json
```

追加のタイマー・ポーリング・描画フレーム処理・高頻度React更新はない。音声チャンクの到着イベントに対して既存Workerで推定する。FFTは選択した更新間隔に制限され、PCMと検出器の大きなバッファを再利用する。
